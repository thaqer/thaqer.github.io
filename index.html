Team of 3 · C++98

webserv

An HTTP/1.1 web server written from scratch with no external libraries. One poll() loop drives every client socket, listening socket and CGI pipe, so nothing blocks. Virtual servers, routes and limits come from an nginx-style config file.

Test dashboard served by the server itself on 127.0.0.1:8080, captured from a local run. A custom 404 page is configured with error_page 404.

What it does

  • GET, POST and DELETE with correct MIME types
  • Directory listing, redirects and file uploads
  • Non-blocking CGI through fork and pipes (Python, PHP, Perl)
  • Chunked request bodies, keep-alive and client timeouts

Notes

  • About 4,200 lines, split into config parser, router, parser and handlers
  • Built with dqaddomi and malsharq; the README says AI was used only as a reference, not for the core logic
  • Root page returned HTTP 200 in my local run

minishell

A Bash-like shell: tokenizer, parser that builds an abstract syntax tree, expander and executor, with pipes, redirections, here-documents and signal handling.

Real session: a pipe, an exported variable, a failing command with its exit status, and a redirect.

  • Builtins: cd, echo, exit, export, pwd, unset
  • Pipelines, > and <<, and && and || operators
  • Built with Daniah (dqaddomi). My commits fixed heredoc issues and added a README for each part

philosophers

The dining philosophers problem with threads and mutexes. A monitor thread stops the run when one philosopher dies or all have eaten enough.

Local runs. With 3 required meals nobody died; with 310 ms to die and 200 ms to eat, a philosopher died at 311 ms.

  • Meal-limit runs exit cleanly with status 0
  • No memory errors or leaks from Valgrind in a short run
  • Modules for initialization, routine, monitor and utilities

cub3D

A first-person 3D engine in the style of Wolfenstein 3D. Walls are drawn with raycasting and the DDA algorithm, using the textures, floor color and ceiling color named in the map file, on top of MLX42.

A real frame from the running game: textured walls, a sky texture over the blue ceiling color, and a green floor, all read from the map file. Captured on a virtual display with software rendering.

  • Four wall textures (north, south, west, east), keyboard movement, mouse look and collision checks
  • Map parser and validator that rejects malformed maps, with separate folders of good and bad test maps
  • About 2,000 lines of C. Built with Daniah (daniah)
  • My commits: fixed memory leaks on bad-map paths, moved allocations to ft_calloc with every result checked, fixed input delay, stutter and slow mouse rotation, and cleaned parsing and norminette issues

Inception

A complete WordPress stack with three custom images built from Debian Bookworm: NGINX as the only entry point over TLS on port 443, WordPress with PHP-FPM, and MariaDB. No prebuilt service images.

Wiring read from docker-compose.yml and the NGINX config. The pulse shows the start order: each service waits for the previous one to pass its healthcheck, mariadb then wordpress then nginx.

Design

  • One bridge network keeps internal ports private; only 443 is published
  • Two named volumes persist the site and the database, and NGINX mounts the site read-only
  • Four Compose secrets hold the passwords, kept out of git and out of environment variables

Documentation

  • User guide and developer guide alongside the README
  • README compares VMs and Docker, secrets and env vars, networks and volumes
